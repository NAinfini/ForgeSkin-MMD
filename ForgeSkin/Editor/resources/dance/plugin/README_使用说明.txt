GTFO MMD Dance 1.1.0（F9 菜单 + v5 全身精确姿势 + 联机同步 / 邀请跳舞）

打开方式：
  进入关卡后按 F9 呼出 / 收起「MMD 舞蹈」面板（黑底白字，鼠标随便点），
  同时按 Esc 打开游戏自带菜单时，面板也会显示在右侧。
  面板打开时会挡住移动/开火/视角；跳舞中开关面板不会切回第一人称，保持当前运镜/第三人称视角。
  F7~F10 那些旧快捷键都不用再按了，全部在面板上点击。

本版重点（1.2.0 · 新舞批量 + 运镜/表情验证）：
  - 新增 5 支舞（动作 + 镜头 + 表情 + 音乐，全部 v6）：
    偶像（212s）、偶像-小三妈（212s）、雨爱DJ（22s）、Darling Dance（211s，无镜头文件）、
    Catch Me If You Can（78s，琳奈用调整骨版本，幅度略大时会比原模型低 3~4cm）。
  - 运镜相机按源 VMD 轨道 1:1 工作（已和 Blender 同帧渲染逐帧对照）；镜头倍率按模型骨骼缩放自动算。
  - 面部表情默认开：开舞后会把后出现的第三人称模型实例也补绑一遍，画面上看到的脸也会动。
  - 舞蹈音乐默认音量 30%，开舞自动播放。

本版重点（1.1.0 · 邀请跳舞）：
  - F9 面板新增「邀请队友一起跳」：队列里有真人队友（不是 AI）时，会列出他们的名字，
    点名字就向对方发出邀请；再点一次可以取消。
  - 对方屏幕上会弹出「跳舞邀请」窗口：按 Y 接受、按 N 拒绝（20 秒不选自动拒绝）。
    弹窗不抢鼠标，跳伞/战斗时也不影响操作。
  - 接受后：对方用游戏自带的 warp 直接传送到邀请者旁边（约 1.1 米），
    1.7 秒后两人同时开始同一支舞；只看得到这两个人跳，旁边没参与的队友不会跟着跳。
  - 停止跳舞、跳完、切歌都会解散队伍；广播式「开始跳舞」不会拉队伍，全房一起跳。
  - 传送在部分状态下可能失败（例如手里抱着任务物品、在梯子上）：warp 失败会退回 TeleportTo，
    再失败对方就原地跳。日志里搜 "net:" 可以看到 "warp/teleport ... ok=..."。

本版重点（1.0.0 · 联机同步）：
  - 新舞蹈「Stay Tonight」（Heaven Lee Ver）：动作 + 运镜 + 音乐，列表里点它再按开始即可。
    数据由 Blender + mmd_tools 从 VMD 直烘（v5 全身姿势 + 相机轨道 + 表情曲线），57 秒、30fps。
  - 房里有别人（也装了本插件 + GTFO-API）时，你点「开始跳舞」会广播这支舞，
    其他人同一时刻（约 0.45 秒后）开始跳同一支舞；你点停止，大家也一起停。
  - 每个人用的都是自己硬盘上的舞蹈文件：收到广播时先比对文件哈希，
    没有这首歌、或文件版本不同（哈希不一致）就只在面板上提示，不会乱跳。
  - 每个人的模型/皮肤仍然是各自本地加载的：想互相看到对方的 MMD 模型，双方都要装好同一套模型。
  - 镜头默认各用各的；打开「联机跟镜头」后，收到别人的舞蹈也会应用舞蹈相机轨道（绕自己的角色）。
  - 需要 GTFO-API（BepInEx/plugins/GTFOModding-GTFO_API）。缺少时插件其余功能照常，联机同步自动关闭。

本版重点（0.7.0）：
  - 新增 v5 舞蹈数据：由 Blender + mmd_tools 直接把 VMD 烘成「每根骨头每帧的世界旋转」。
    模型上的全部骨头都由它精确驱动——腕捩1-3、手捩1-3、足D/ひざD/足首D、脚趾、肩调整、
    腰キャンセル、裙摆/头发等模型自带的骨头都在里面，不再用近似扭转，所以大动作时手臂不会拧坏。
  - 新舞蹈：CH4NGE（动作 + 镜头 + 音乐）。F9 → 列表里点 CH4NGE → ▶ 开始跳舞。
  - 旧的 CH4NGE-Kafu（v3）仍然保留，方便对比。

面板内容：
  舞蹈列表        点击选择要跳的舞蹈（读取 Dances 目录下的 *.dance，
                  同名的 .cam / .face / .wav 自动带上；超过 12 个时用滚轮翻页）
  运镜相机        按源 VMD 相机轨道运镜（默认关；开舞不会强制打开，和第三人称互斥）
  第三人称        镜头拉到角色身后
  面部表情        跟随舞蹈表情曲线（模型带表情时有效）
  场景补全        运镜时把镜头附近被剔除的场景渲染回来
  自动眨眼        不跳舞时每几秒眨一次眼
  隐藏持枪手臂    跳舞时隐藏第一人称持枪手臂（默认开）
  扭转骨骼        只对旧的 v3 舞蹈有效（v5 的扭转是精确数据，不需要这个开关）
  重新绑定骨骼    跳舞中模型换装/重生后，重新找一遍模型骨骼
  邀请队友        列出队伍里的真人玩家，点击发出邀请（再点取消）；
                  对方按 Y 接受后会被传送到你旁边一起跳，按 N 拒绝
  联机同步        开：开始/停止会广播给房里其他装本插件的人（默认开）
  联机跟镜头      收到别人的舞蹈时也应用舞蹈相机轨道（默认关，保持自己的视角）
  音量  − / ＋    舞蹈音乐音量（5% 一档，默认 30%，开舞自动播放）
  ▶ 开始跳舞      载入当前选中的舞蹈并开始
  ■ 强制停止      立刻停止并恢复原动作

说明：
  - 会在场景里查找所有玩家骨架（含 AI 队友），找到后一起跳，方便测试。
  - 跳舞期间会临时接管这些角色的动作，播完/停止后恢复原状。
  - v5/v6 的模型驱动方式：按 VMD 烘出的每根骨头「世界旋转 + 世界位移」绝对值摆放（v6 起含
    腰/グルーブ/センター 的升降与走位），只叠加玩家转身/朝向的变化。蹲下时胯跟着降、脚留在地面，
    走位按原编舞移动（7Rings 全场约 1.5 m）；落地由模型静置时的鞋底平面决定，没有运行时贴地伺服。
    玩家走位/上下楼梯时模型零延迟跟随：开舞时按"鞋底=地面"标定一次高度偏移，
    之后模型根每帧直接按"玩家脚点高度 + 这个常量"摆放（零延迟、无射线、也不会跟着身体动画上下晃）。
  - 音乐从角色位置播放（非 3D 衰减），只有你自己能听到；联机时每个人各放各的本地 .wav，
    靠“同时开始”对齐，音乐本身不联网传输。
  - 邀请跳舞和广播同步都要求双方装着同样的 .dance 文件（哈希一致）和同样的模型皮肤；
    对话用的是 GTFO-API 的定向消息，只有被邀请的人会收到。
  - 联机同步的事件名是 "GtfoMmdDance.Sync"（走 GTFO-API 的 NetworkAPI，GameOrderCritical 可靠通道），
    包体只有 25 字节 + 曲名。没装本插件的人收到这个包会被游戏/GTFO-API 丢掉，不受影响。
  - 关闭游戏菜单后运镜才接管镜头；菜单打开时完全交还给游戏。
  - 布料物理已移除（FPS 开销大）：头发/裙子不再由插件模拟；ForgeSkin 角色身上的布料
    仍由 ForgeSkin 自己的 ChainPhysics 计算，插件只负责不覆盖那些骨头。

日志：
  <profile>\BepInEx\LogOutput.log
  搜索 "GTFO MMD Dance" / "full pose bound" / "dance start" / "dance loaded" 可确认状态。
  联机问题搜 "net:"（联机同步已注册 / 广播开始 / 收到开始 / 哈希不一致 / 发送失败）。
  如果按 F9 没有出现面板，把 "focus=... game=..." 那几行发过来即可定位。

数据格式（.dance v6，旧 v3/v4/v5 仍可播）：
  magic "DNCE"，version=6，frames，joints(50)，rate(30)，名称，髋骨名，
  每帧：50 个四元数（标准关节 turn）+ 3 个 float（髋位移），
  然后旋转 track 数；每个 track：骨头名 + 每帧四元数（世界旋转相对静置的增量）；
  然后位移 track 数；每个 track：骨头名 + 每帧 3 个 float（世界位置相对静置的增量）。
  v6 说明：MMD 的蹲/跳/走位记在「腰」「グルーブ」「センター」等骨头自己的**位置**轨道上，
  v5 只烘旋转，所以蹲多深脚就浮多高；v6 把这些位置增量也烘进来，胯和脚都按 Blender
  解算的真实高度摆，落地点由模型静置时的鞋底平面决定，不再靠运行时贴地伺服去猜。
  同名 .cam（CAM2 相机轨道）、.wav（音乐）、.face（表情曲线）自动加载。

人物模型（.unity3d 直读，1.2.0 新增）：
  把 7DTD / VRChat 人物包（*.unity3d）丢进 BepInEx\plugins\GtfoMmdDance\Avatars\，
  按 F9 打开面板，底部「人物模型」一栏点「换上 …」即可，再点一次「卸下 …」恢复原角色。
  - 不需要转换：插件自己解析 UnityFS（AssetsTools.NET），把骨骼层级、SkinnedMeshRenderer、
    网格（顶点/法线/切线/UV/颜色/骨骼权重/索引/bindpose）、贴图（DXT1/DXT5/BC7 解码）和
    材质重建到 2019 引擎里，再用 Shaders\liltoon2019 这套 2019 编译的 lilToon 还原观感。
  - 一个包里通常有好几个 prefab（例如 Eku / Milfy_Itazura / Eku猫猫女仆装），
    插件默认挑「名字和文件名一致」的那个，否则挑网格最多的；CustomArms 那套第一人称手臂会整棵跳过。
  - 姿势：主骨架映射 50 个标准人形关节（Hips/Spine/Chest/Neck/Head/四肢 + 30 根手指），
    衣服/尾巴那些挂在复制骨架（Hips_女仆装 …）上的再绑一份带后缀的映射，两条一起跟着身体。
  - 载入时原角色渲染器会被隐藏，卸载后自动恢复（每秒还会再扫一遍，
    防止 ForgeSkin 在跳舞开始时重新生成的模型露出来）。
  - 第一次点击会有几秒卡顿（97MB 的包要解压 + 44 张贴图解码），日志里会打到毫秒数。
  - 注意：舞蹈动作目前还是写给 ForgeSkin 模型骨架的，运行时模型暂时只跟身体的待机/动作姿势；
    舞蹈数据到 VRoid 骨名的映射还没接（下一步做）。
  日志搜 "avatar" 可看到：
    avatar: root '…'       选了哪个 prefab
    avatar: fit …          按身高缩放（bodyStature/modelStature/localScale）
    avatar: floor align …  落地校正的偏移量
    avatar: persons hide=… 压原角色是否成功
    avatar: dance: …       舞蹈骨名映射（bound=…）
  - 面板里「换上了模型」之后会多出一行「身高 −/＋」，按 2% 微调（动漫模型腿长比例和士兵骨架不一样，
    自动缩放是按头顶骨到脚骨算的，觉得太高/太矮就点几下）。
  - 第一人称的手臂目前还是游戏原版（模型自己的手臂还在做）。
